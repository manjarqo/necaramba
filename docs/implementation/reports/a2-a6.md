# A2–A6 deterministic core implementation

Date: 2026-10-14. Worktree: `.worktrees/core`, branch `impl/core`.

## Implemented slice

- A2: Unicode grapheme selection conversion, direct mapping and bounded uppercase fallback; explicit physical mapping entries keyed by physical keycode and complete modifier set. The legacy planned signature supports **only explicit test IDs US/RU and ANSI alphabet reference keys** and validates supplied character pairs against the reference target. It never reads event text. Unknown IDs/keycodes/modifiers return nil. Real US/ABC/Russian/Russian-PC IDs and ANSI/ISO/JIS punctuation require platform-captured maps from B.
- A3: bounded physical word buffer (128 graphemes/512 UTF16 units), delimiter emitted separately exactly once, context/layout equality, paste/navigation/chord/synthetic invalidation. Overflow discards input through the next delimiter. Own tagged events are ignored. Normal backspace invalidates; `consumeConfirmedBackspace` is available only after an adapter proves final tracked-grapheme deletion.
- A4: immutable NFC/case-fold lexical index, exact typo and unambiguous exact yo rules, lexical double-caps correction, case preservation, unknown-source/known-target layout conversion, one combined correction. Both known candidates or conflicting rules abstain. URL/email/path/digit/code/mixed-language/all-caps tokens are protected. Physically confirmed Caps Lock permits uppercase layout conversion while retaining explicit protected-word checks. Exclusions cover source, intermediate and final candidates. Synthetic RulesV1 is a test resource only.
- A5: safety gates precede app override, profile, global flag; safe manual commands remain available when automatic policy is disabled. Exhaustive 192-combination table verifies booleans.
- A6: pure bounded modifier FSM, delayed Single Shift, same/mixed-side Double Shift, overlapping Split Shift once, Option opt-in, chord cancellation, repeat/duplicate handling, monotonic scheduler input, epoch invalidation. No timers, system APIs or event suppression in core.

## Interfaces for B/C/D

The signatures listed in plan A are present, with explicit public initializers for every added public struct.

Additional adapter-facing interfaces:

```swift
PhysicalLayoutMapping(source: LayoutID, target: LayoutID, entries: [PhysicalLayoutMapping.Entry])
PhysicalLayoutMapping.Entry(keyCode: UInt16, modifiers: Set<Modifier>, text: String)
LayoutConverter.convert(keys: [InputEvent], to: LayoutID, physicalMappings: [PhysicalLayoutMapping]) -> String?
LinguisticEngine(snapshot: RuleSnapshot, physicalMappings: [PhysicalLayoutMapping] = [])
WordBuffer.consumeConfirmedBackspace(_ event: InputEvent) -> Bool
```

Physical mapping entries are hardware-qualified data supplied by the composition root; no mapping is inferred from a localized layout name. Duplicate matching physical entries abstain. Source/target key sequences must share context/layout; mismatched BufferedWord metadata yields unsupportedLayout.

`Correction.original` and `replacement` contain the token **without delimiter**; `BufferedWord.delimiter` remains a separate trigger preserved by the native edit transaction. Own events are ignored; runtime must explicitly invalidate around state changes and external editing. `GestureRecognizer.advance(to:)` receives monotonic nanoseconds from the scheduler. `invalidate()` removes pending actions but does not send key events or suppress genuine releases.

The engine's `preferences.autoEnabled` gate is a precondition. When PolicyResolver permits an explicit app allow despite the global auto flag, B should pass the effective auto permission into the classifier preferences, retaining typo/yo flags, or expose an explicit effective-policy input in a subsequent contract revision. Calling the engine with the unchanged global-off snapshot intentionally returns disabled.

## Review regression revision (2026-10-14)

Review found and reproduced these behavior failures before changing production code:

1. Left Shift → ordinary letter → Right Shift incorrectly emitted Split Shift toggle.
2. An ordinary repeated key while Shift/Option was held bypassed cancellation and produced a delayed switch/manual action.
3. `éф`, `øя`, Greek/ASCII mixtures and unsupported scripts bypassed the ASCII-only Latin detector.
4. Actual WordBuffer → LinguisticEngine streams for `teh.com `, `teh:com ` and `teh://com ` incorrectly replaced the prefix before seeing the remainder.

Fixed cancellation precedence; only repeat events of Shift/Option themselves are ignored. Split toggle requires an uncancelled chord before the second physical Shift. TokenGuard first NFC-normalizes and accepts only the supported ASCII English/Russian letters for automatic rules; accented Latin, other scripts and mixtures abstain conservatively. NFC lookup still equates composed/decomposed forms, but unsupported accents are protected even when present in a test lexicon.

Updated automatic boundaries: whitespace and terminal `!`/`?` may emit a word. Dot, slash, colon, comma, semicolon and other punctuation invalidate the current word; trust remains broken until an unambiguous whitespace boundary. These punctuation-triggered automatic corrections are intentionally unsupported pending a token grammar/context design. Manual selection conversion remains unchanged.

Regression tests exercise actual buffering plus the engine on dot, colon, slash, email, protocol and malformed repeated-dot streams. Final `swift test`: **35 XCTest tests, 0 failures**, including the existing million-event replay. No device/editor/release tests were run for this revision. RED log `/tmp/necaramba-review-red.log`, GREEN `/tmp/necaramba-review-green.log` (temporary logs).

## Deferred terminal punctuation revision (2026-10-14)

A further streaming RED reproduced `teh!name@example.com ` and `teh?name@example.com ` incorrectly correcting `teh` before recognizing the email continuation. No punctuation now emits an automatic word immediately. Trailing `!`/`?` is held in bounded pending state; whitespace emits the original letter token with `pendingPunctuation + whitespace` as the delimiter. Thus `ghbdtn! ` remains eligible and preserves `! ` in the native transaction. Any following non-whitespace/non-terminal-punctuation input invalidates the entire token until whitespace. Pending punctuation counts toward both grapheme and UTF16 limits and is erased on invalidation. Confirmed letter-suffix backspace conservatively declines when punctuation is pending, rather than deleting a tracked letter under a different suffix.

RED assertions observed premature emissions/email corrections, lost delimiter and missing pending bounds. Final `swift test`: **38 XCTest tests, 0 failures**, including the million-event replay. No manual/editor tests run. Temporary logs: `/tmp/necaramba-punctuation-red.log`, `/tmp/necaramba-punctuation-backspace-red.log`, `/tmp/necaramba-punctuation-green.log`.
