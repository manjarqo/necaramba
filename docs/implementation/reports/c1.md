# C1 local rules storage

Implemented Foundation-only immutable records, repository ports and Unicode validation in NecarambaCore; SQLite prepared statements, serial access, migrations, backup and own JSON v1 archives in NecarambaMac. UI additions use trim/NFC, 1–20 graphemes, NFC case-insensitive POSIX lookup, Unicode control/=/percent rejection and digit-containing tokens without letters rejected. Emoji ZWJ remains legal. Legacy archive21–100 values are retained separately with their original UTF-8 bytes and exported; >100 rejects import. Import validates all records and conflicts before inserts in BEGIN IMMEDIATE; SQL failures roll back. Backup uses sqlite3_backup and includes uncheckpointed WAL state.

Migration admits a fresh database or only the explicit own v0 fixture schema (word_rules columns id/normalized/original/created_at/share_opt_in). It does not infer arbitrary older formats or import any third-party store. It checks integrity, rejects newer/inconsistent migration versions, backs up an existing supported v0 database before transaction, and rolls back failed migration without advancing version. It repartitions existing long rules without truncation. Unsupported/corrupt files are retained. No restoration by overwriting a live DB is attempted: transactional migration rollback preserves original rows, with the separate backup available for recovery.

## Integration

Package.swift belongs to the integrator and is not committed here. Add `.systemLibrary(name: "CSQLite")`, and add `CSQLite` plus `NecarambaCore` to NecarambaMac dependencies. Sources/CSQLite provides portable shim/modulemap linking sqlite3. No pkgConfig is needed on macOS. Test dependencies: NecarambaCoreTests→NecarambaCore; NecarambaMacTests→NecarambaMac, NecarambaCore and CSQLite.

SQLiteStore exposes specified methods plus `legacyWords()` and `backup(to:)`. Legacy removal/editing is deliberately not the regular UI word-edit API. Data consumers must obtain snapshots after storage commit, outside the keyboard callback. Combined preferences+rules recovery journal belongs to C2; C1 export covers rules only.

## Review corrections

Review identified incompatible nullable schemas, lowercase persisted UUID identities, and NUL truncation in app display names. Added regression tests before fixes. RED evidence: nullable v0 original/normalized crashed in `String(cString:)`; lowercase v0 IDs left the long row in both categories and caused export/import rejection; app NUL set/import succeeded and truncated/replaced persisted names. All reproduced on 2026-10-14 before changes.

Schema admission now checks declared column types, NOT NULL flags and primary-key positions for all v1 tables, plus normalized unique indexes on both word tables; v0 uses the same strict word-schema admission. Defensive SQLite text decoding checks TEXT/non-null/UTF-8 and reads explicit byte lengths, throwing on unexpected NULL instead of crashing. Existing supported v0 UUID text is canonicalized inside the migration transaction before legacy partitioning; UUID aliases are rejected before mutation, and UI deletion handles case-insensitive persisted UUIDs. App display-name controls including NUL reject set/import before commit, preserving previous values.

Final `swift test --filter 'SQLiteStoreTests|RuleValidationTests'`: **16 tests passed, 0 failures** after formatting. Added fixtures cover nullable v0 row preservation, malformed nullable v1, unexpected NULL IDs during reads/export, lowercase UUID short/long migration with export/import and delete/reopen, and app NUL rejection with persisted old values. Platform/manual gates remain unrun as above.
