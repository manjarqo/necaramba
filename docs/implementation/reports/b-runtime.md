# Native runtime and review round 1

The original slice's AX whole-value rewrite has been removed. AXSelectionAdapter contains no AX setters. It obtains direct frontmost PID/control, exact retained AX element identity, text/range and inactive composition proof outside the tap; missing AXMarkedTextRange is unsupported. Secure Input is checked synchronously. SelectionEvidence carries an opaque UUID bound to the retained element. Read materialization and selected/plain text have a 1 MiB ceiling.

Edits use a prebuilt marked key-event batch on the dedicated default tap executor: at most 512 events, at most 1024 replacement UTF16 units, at most 128 suffix graphemes, at most 10 ms of posting. Each key has paired down/up; Unicode chunks preserve scalar boundaries. Preparation passes physical input through. Generation changes during preparation abort before mutation. The commit closure has no AX, filesystem/network, tasks, waits or run-loop reentrancy. Hardware callbacks cannot interleave with that bounded batch. A partial posting failure returns uncertain without retry or rollback.

CGEvent posting is NOT final commit evidence. After releasing ownership, AXSelectionAdapter reads back the exact retained element, replacement range and caret, checking unchanged physical generation before and after readback. Replayed held physical input advances generation. No readback/no acknowledgement/continued typing means uncertain, context quarantine and cleared pending work/undo. Counts, sound and journal are created only after this proof and verified TIS readback. No native host is qualified yet.

CmdShiftV now has a native interception path for a cached qualified context. Its trigger and following physical events enter the same ownership controller (capacity 16, preparation deadline 100 ms). Before mutation, overflow/deadline abort and replay in original order. Failure replays the original chord once only while its original context remains valid; a stale-focus chord is cancelled rather than pasted into another control. Success/uncertain discard the trigger down/up and replay following physical input. If V-up arrives after completion, it is suppressed as the matching owned release. There is no clipboard rewrite: explicit plain text is inserted through the same proven selection/key strategy.

EditOwnership is tested through 100000 queued physical events across committed replacement, stale/focus generation, capacity overflow and partial failure. Exact event order/count and simulated editor contents are asserted. ReplayRunner now executes every declared JSON scenario, rejects unknown scenarios, and runs both the production InputRuntime pass replay and the ownership edit/overflow replay. These are simulated checks, not compatibility evidence.

Non-editing gestures use a separate application/layout-only GestureContextReading port. Single Shift layout changes and split-Shift preference toggles require listen capability and inactive Secure Input, without post permission or editable AX focus. The tap runs listen-only when post access is absent; interception/text mutation remains disabled. Two fake-context tests verify layout/preference gestures in unsupported editors.

Manual action order is selected text → valid own undo → tracked word. Shift/Option flags do not clear journal entries. Manual selected conversion records one inverse journal entry; an own TIS change refreshes epochs before recording it. External layout changes update the runtime's actual layout and invalidate unrelated undo. ContextMonitor exposes onLayoutChanged; ContextRefreshing is a Core port. A pending word, old rule or old preference delivery is cancelled on updates.

LinguisticEngine is compiled once per snapshot, including actual TIS physical mappings. install(snapshot,onInstalled:) resolves corpus aliases only when every advertised pair matches actual hardware translations and the source/target pair is unique. Ambiguity disables that mapping. Compilation runs on a serial background queue; engine/rules/runtime swap together on main after any active synchronous batch completes. onInstalled(version) fires after the actual swap. The facade uses this cached engine for boundary correction. Early correction is opt-in through corpusQualified, uses the same classifier and immutable context, and remains disabled in production. Its simulated ghbdtn→привет followed by ! test passes.

Public composition API remains NativeInputController(profiles:layouts:permissions:preferences:snapshot:corpusQualified:), lifecycle, preferences/rules/word+app policies, manualCorrection, plainPaste, undoLast. New callbacks: onCommitted(UUID,CounterKind) fires exactly once for committed auto/manual/undo; combined corrections count layout as primary. onResult remains count/status only. No input text crosses a channel.

## Remaining release gates

Default CapabilityProfiles contains no qualified entries and corpusQualified defaults false. Root observed permissions unavailable; real host runs remain UNRUN. AXMarkedTextRange absence, unsupported key semantics, unproved Unicode insertion, oversized bounded batch and ambiguous layouts all abort. The production app cannot use these paths until an actual control/hardware/OS revision passes qualification.

Copy fallback remains unsupported: NSPasteboard changeCount cannot identify whether our Copy command or an external producer wrote the new generation. A qualified app acknowledgement/source proof is required before clipboard text can stand in for selection evidence. No source proof is fabricated.

Physical focus/IME/Secure Input, key-post failure injection, native autocorrect, clipboard multi-item host behavior, p99/idle CPU/RSS, macOS12 and Intel/Apple Silicon release checks remain UNRUN. Automated ownership/early tests use a synthetic editor. They do not claim release compatibility or target acknowledgement.

RuleSnapshotConsumer temporary declaration remains in Core/Ports/Editing.swift; root removes it when merging delivery's canonical Core/Delivery declaration. Protocol install now enqueues compilation; use the facade completion callback for published active version.
