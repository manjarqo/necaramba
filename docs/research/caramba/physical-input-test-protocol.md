# Протокол проверки клавиатурных событий

Дата: 2026-10-14. Цель: подтвердить наблюдаемое преобразование `ghbdtn` → `привет` и жесты Shift в отдельном пустом документе TextEdit.

**Статус: BLOCKED / UNVERIFIED. Тестовые клавиши не отправлялись; scratch-документ не создавался.**

## Конкретные блокеры

1. В прочитанном AX-дереве Caramba плитка автопереключения представлена как `изображение feature-tiles/autoswitching`, без `Value`, checked или selected. На снимке она серая. Цвет сам по себе не даёт надёжного доказательства состояния и обратимого восстановления настройки; этот переключатель не нажимался.
2. AX-дерево доступного главного окна Caramba не содержит индикатор активного системного источника ввода. Первоначально источник был неизвестен; последующее read-only чтение Carbon установило `com.apple.keylayout.Russian`. Этот блокер устранён (см. дополнение ниже), но состояние автоматики остаётся неизвестным.
3. `typeText`/`paste` не использовались как замена физическим клавишам: Unicode-ввод или вставка могут обходить анализ обычной последовательности клавиатурных событий. Даже CUA `pressKey` создаёт синтетические события; будущий результат следует маркировать именно как проверку синтетическими отдельными клавишами и отдельно сравнить с аппаратной клавиатурой.

Блокер ограничен использованным интерфейсом наблюдения; это не утверждение о невозможности получить состояние другими разрешёнными способами или проверить продукт вручную.

## Дополнительное точечное чтение состояния

Через Swift/Carbon вызваны `TISCopyCurrentKeyboardInputSource()` и `TISGetInputSourceProperty(..., kTISPropertyInputSourceID)`. Результат: **`com.apple.keylayout.Russian`**. Источник не изменялся.

Для единственного нужного ключа `tech.caramba.switcher.auto-enabled` предпринято чтение точного файла `/Users/manjarqo/Library/Containers/tech.caramba.switcher/Data/Library/Preferences/tech.caramba.switcher.plist`. `PlistBuddy Print` дал неоднозначную ошибку о несуществующем файле. `stat` подтвердил, что файл существует, размер 3297 байт, дата изменения 2026-10-12. Затем Python `plistlib` при открытии этого же файла завершился **`PermissionError: [Errno 1] Operation not permitted`**. Значение ключа не прочитано, содержимое профиля не выводилось; поиск по другим личным каталогам и обход разрешений не выполнялись. Для исходного состояния автоматики сохраняется конкретный блокер доступа к данным. Настройки, источник ввода и документы не изменялись.
