# Ядро ввода и формат модели: дополнение к native findings

Дата: 2026-10-14. Источник — arm64 Ghidra/REA псевдокод в `decompiled/main-arm64`. Каждый файл содержит Evidence ID. Адреса ниже принадлежат основному executable. Это анализ ветвей и вызовов, не протокол исполненного ввода; типы и ABI в псевдокоде могут быть восстановлены неверно.

## Поток события

`0x100049b20` создаёт основной tap с mask `0x1c06`; callback `0x100049bec` передаёт обработку `0x10004bff4`. Здесь видны проверки AX trust, восстановление disabled tap, обработка flagsChanged/Split Shift, Secure Input gate. Затем событие попадает в Rust-часть `0x100230dd8`.

`0x100230dd8` разделяет mouse events 1/2, keyDown 10, keyUp 11 и flagsChanged 12, формирует внутренние записи в thread-local state и вызывает `0x100224414`. Некоторые ветви возвращают NULL вместо события — перехват может подавлять исходный ввод. Точное условие каждой suppression-ветви требует трассы на контролируемом host.

`0x100224414` — крупная state machine (более 2000 строк псевдокода). Видны работа с буфером, key codes `0x38/0x3c` (Shift), `0x3a/0x3d` (Option), ветви single/double Shift, автоисправления, ё, double caps, autoswitch/collision, изменения выделения. Есть проверка общего префикса перед повторным вводом: не всякое исправление удаляет слово целиком. Метки действий в строках помогают связать ветви, но не доказывают реальные analytics payload.

Второй tap создаётся `0x1001ac678` с mask `0x1c00`; callback `0x1001a6ca4` возвращает исходное событие. Он не равен основному преобразователю; назначение permission/probe — гипотеза.

## Замена и раскладка

`0x10022c820` активирует input source, читает текущий источник обратно, выполняет ограниченные повторные попытки и управляет задержками между активацией, backspace и retyping. Найдены верхние границы: число retries не больше 10, retry delay и отдельные межстадийные задержки не больше 500 мс. Это пределы конфигурации, не установленные значения по умолчанию. Один символ Ghidra ошибочно именует как Swift initializer, хотя связывание указывает на TISSelectInputSource; имена процедур нельзя принимать буквально.

Эта процедура может отправлять Space `0x31`, Backspace `0x33`, затем воспроизводить keycode/modifier records через `0x10022caa8`. Ветви и flags меняются по состоянию; нельзя заменить их утверждением «всегда N backspaces». Wrapper-функции `0x1000812cc`, `0x1000816c8`, `0x1000818d0`, `0x100081b50`, `0x100081e14` используют CGEventPostToPid; имеются и пути глобального CGEventPost.

`0x1002284ac` и `0x10022acd4` связывают layout data и UCKeyTranslate; во второй процедуре виден буфер до четырёх UTF-16 units. Это преобразование клавиатурной раскладки, не фонетическая транслитерация.

Plain paste: `0x10002e138` сохраняет pasteboard types/data, публикует plain string, инициирует вставку и асинхронную задержку около секунды; продолжения `0x10002e46c/0x10002e4e4` ведут к восстановлению `0x10002e8a0`. В этих ограниченных процедурах не установлена проверка changeCount перед restore. Это основание спроектировать такую проверку в аналоге, но недостаточно для универсального утверждения об ошибке оригинала.

## CLM1

Ресурс `evidence/resources-assets/model.macos.bin`: 1 565 707 bytes, SHA-256 `3f411eef7a1a6d502c1029924a9c982761d319fc67d23f16b34c725fdfcb3f69`. Байты ресурса сохранены только как локальный исследовательский артефакт и не являются данными нового продукта.

Парсер `0x1002af5dc` проверяет:

| Offset | Length | Значение/интерпретация |
|---|---:|---|
| 0 | 4 | magic CLM1 |
| 4 | 1 | поддерживается version 1 |
| 5 | 1 | требуется 0 |
| 6 | 4 | big-endian identifier для выбора записи ключа |
| 10 | 12 | nonce-подобное поле, передаётся в stream cipher state |
| 22 | 4 | big-endian payload length N |
| 26 | N | payload |
| 26+N | 64 | signature-подобные bytes; общий размер обязан быть N+90 |

Проверка подписи связана с `0x10037a22c` и `0x100371078` над header+payload; затем `0x1002b6598` готовит 32-byte key material, состояние содержит `expand 32-byte k`, nonce и нулевой counter. `0x1002b9e20` обрабатывает поток; `0x1002a764c` ведёт к unpack/decompression, `0x1002af994` — к разбору структуры. Семейство ChaCha уверенно предполагается по константе и структуре, но точный вариант/число rounds здесь не проверены тестовым вектором. Полный payload не расшифрован и список слов/весов не восстановлен.

Строки схемы и Rust source paths показывают DAWG dictionary, classifier, layout converter и группы `Kbm`, `Feats`, `AutocorrectRule`, `KbmFeature`, `AppexRuleSet`, `Logos`. В частности: `prefix_len`, `suffix_len`, `insert_id`, `case_sensitive`, `is_yofikator`, `weight`, `is_known_word`, `is_double_caps_preventative`, layout retry/delay и `switch_to_en_on_focus`. Их присутствие не устанавливает все значения и приоритеты действующей модели.

## Вывод для аналога и оставшиеся вопросы

Независимая реализация должна иметь собственные раскладочные таблицы, словари/правила и корпус оценки. Числовые пороги, Unicode edge cases, отмена, ранняя коррекция до разделителя, app profiles и жесты требуют differential tests. Извлечённый CLM1 не включать в distribution.

Из списка «Что необходимо дочитать» в `native-findings.md` здесь частично закрыты dispatch `0x100230dd8`, второй callback и replacement/layout chain. Foreground predicate `0x1001d4b38`, regex fallback `0x100230964`, точные classifier weights и все динамические ветви остаются открытыми. Покрытие декомпиляции не отменяет эти ограничения.
