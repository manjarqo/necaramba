# Публичные функции Caramba и ограничения платформы macOS

Дата проверки: 2026-10-14. Назначение: доказательная записка для спецификации независимого аналога. Это исследование документации; поведение установленного приложения здесь не объявляется проверенным. Версия локального эталона, сообщённая основным исследователем: 2026.09.22 (20260922.2). Целевой стек, подтверждённый пользователем: Swift/AppKit, macOS 12+, arm64 и x86_64.

## 1. Заявления производителя

| Автоматика | Исправление раскладки и частых русских/английских опечаток, двойной начальной заглавной |
| Ё | Расстановка ё по языковым правилам |

Сайт общий для Windows/macOS: Pause Break, Games и парольная эвристика требуют отдельной проверки на Mac. Маркетинговое утверждение о синхронизации функций не доказывает идентичность платформенных механизмов. Рассказы прессы на странице относятся к разным годам и версиям.

Отдельные macOS-сведения из [карточки App Store и истории версий](https://apps.apple.com/ru/app/caramba-switcher-pro/id1565826179?mt=12): требуется macOS 12+, интерфейс RU/EN, встроенные покупки. История 2026.09.20 сообщает об удалении автоматического добавления исключений после повторного набора при сохранении старых исключений. Более поздняя 2026.09.22 касается панели приложений и Spotlight. В истории есть работа с аббревиатурами/цифрами и регистром, исключения для ё, капитализация географических названий с учётом неоднозначности. Это заявления разработчика, не измеренная точность модели.

**Противоречие:** общее обещание обучения на сайте расходится с конкретным changelog об отмене автоматического создания исключений. Для эталона 2026.09.22 приоритет у версионного changelog и затем у воспроизведённого поведения. Не включать старое автообучение в обязательную совместимость без отдельного доказательства.

[Справка производителя о Secure Input](https://caramba-switcher.com/help/secure-input/) объясняет отсутствие реакции на клавиатуру при активной защите ввода. Это штатное ограничение, а не необходимость обхода защиты.

## 2. Что публичные материалы не доказывают

- Наличие конкретной архитектуры нейросети, набор весов, точные словари и порядок правил.
- Использование AX для чтения текста: наличие Accessibility onboarding само по себе этого не устанавливает.
- Точные жесты и интервалы DoubleShift, способ отмены, транзакционность правок и работа с выделением.
- Реализацию очистки форматирования, полного восстановления clipboard, Unicode и emoji.
- Точное поведение терминалов, браузерных password-полей, IDE, игр, RDP, IME, приложений с собственной текстовой системой.
- Гарантированную возможность повторить Mac App Store-дистрибуцию другим приложением.

Для этих пунктов нужны доказательства из бинарника/ресурсов или отдельная таблица поведенческих тестов. Публичные сведения следует маркировать `vendor-claim`, локальные строки/символы `static-evidence`, реально воспроизведённые сценарии `observed`, проектные решения `design`.

## 3. Захват ввода и разрешения

[CGEvent](https://developer.apple.com/documentation/coregraphics/cgevent) предоставляет event taps, управление включением tap, создание/публикацию клавиатурных событий. Проектный вывод: синхронный callback должен выполнять только ограниченный разбор и решение по событию, без сети, диска и блокирующего AX; работу UI и обновление модели вынести из callback.

Проверены также первичные заголовки установленного Apple SDK:

- `.../CoreGraphics.framework/Versions/A/Headers/CGEvent.h`: `CGPreflightListenEventAccess` и `CGRequestListenEventAccess` (строки 398–402), отдельные `CGPreflightPostEventAccess`/`CGRequestPostEventAccess` (404–408), все доступны с macOS 10.15.
- Там же: отключение неотзывчивого tap и `CGEventTapEnable` (320–328). Проектировать ограниченное восстановление после timeout, но не бесконечное насильственное включение после явного пользовательского отключения.
- Там же, строки 196–203: потребитель может игнорировать Unicode payload и переводить virtual keycode самостоятельно. Следовательно, `keyboardSetUnicodeString` не гарантирует одинаковый ввод во все программы.

Полный SDK root этой машины: `/Applications/Xcode.app/Contents/Developer/Platforms/MacOSX.platform/Developer/SDKs/MacOSX.sdk/System/Library/Frameworks`.

Разделять возможности `listen`, `post`, `AX trust` и состояние tap; не сводить их к одному сохранённому флагу. Проверять фактический результат API и обновлять состояние после возврата из System Settings. Синтетическим событиям назначать собственную метку и исключать их из повторной обработки. При недоступности прав ввод должен проходить неизменённым.

## 4. Раскладки и Unicode

[Документация NSTextInputContext](https://developer.apple.com/documentation/appkit/nstextinputcontext/keyboardinputsources) подтверждает идентификацию раскладок через TIS ID. Конкретные операции дополнительно проверены в первичном Apple SDK `Carbon.framework/Versions/A/Frameworks/HIToolbox.framework/Versions/A/Headers/TextInputSources.h`:

| API/свойство | Доказательство в заголовке | Следствие для проекта |
|---|---|---|
| `TISCopyCurrentKeyboardInputSource` | 787–799 | Получать действующий источник, не хранить только собственную догадку |
| `TISSelectInputSource` | 952–985 | Проверять OSStatus и фактический выбранный источник |
| `kTISPropertyUnicodeKeyLayoutData` | 431–451 | Значение может быть NULL; IME не считать обычной раскладкой |
| `kTISNotifySelectedKeyboardInputSourceChanged` | 1080–1091 | Сбрасывать неподтверждённый буфер при внешней смене раскладки |
| `kTISNotifyEnabledKeyboardInputSourcesChanged` | 1093–1104 | Обновлять набор поддерживаемых источников |

Проектный вывод: отдельный LayoutAdapter для US/ABC, Russian, Russian-PC; преобразование по клавишам/раскладкам, включая пунктуацию и Shift. Нельзя подменять layout-conversion простой транслитерацией. При IME/composition, dead keys или неизвестной раскладке автоматические правки отключать до реализации и проверки явной поддержки. Длины `String`, UTF-16 AX range и количества Backspace различаются; emoji, комбинируемые символы и суррогатные пары должны входить в тесты.

## 5. Secure Input и конфиденциальность

[Apple TN2150](https://developer.apple.com/library/archive/technotes/tn2150/_index.html) описывает защиту чувствительного ввода от перехвата другими процессами. Документ архивный; актуальное поведение каждой целевой macOS проверять экспериментально.

Проектное правило: при Secure Input прекращать сбор контекста и замены, очищать текущий текстовый буфер/undo; после выхода начинать новый контекст. Не пытаться выключать защиту другого приложения. Не требовать Screen Recording или Full Disk Access для базового клавиатурного сценария. Диагностика содержит причины решений, коды ошибок и задержки, но не пользовательский текст по умолчанию.

## 6. Замена текста, отмена и pasteboard

[AXUIElementSetAttributeValue](https://developer.apple.com/documentation/applicationservices/1460434-axuielementsetattributevalue) допускает ошибки unsupported, invalid element, cannotComplete и notImplemented. Проектное следствие: перед AX-заменой проверять доступность/settable атрибута и актуальность фокуса; отсутствие поддержки является ожидаемым состоянием. AX-вызов не равнозначен гарантированной записи в undo manager чужого редактора.

Возможны три адаптера замены:

1. AX replacement для проверенных обычных полей с контролем выделения и подтверждением результата.
2. Ограниченные синтетические key events для приложения, где проверена семантика удаления/вставки.
3. Copy/transform/paste по явной команде для выделенного текста, если доступен clipboard и пользователь допускает временную подмену.

Это альтернативы, а не порядок fallback. Основной исследователь сообщил о `CGEventTapCreate`, `CGEventPost/PostToPid`, TIS и `IsSecureEventInputEnabled` в импортах эталона; AXUI imports в проверке `nm` не найдены. Поэтому event-tap/key-event путь — первичный кандидат для совместимости; AX — отдельное расширение с другими ограничениями распространения. Отсутствие импорта не доказывает отсутствие динамического использования API. Не использовать глобальный Cmd+Z как универсальную отмену: он может отменить собственное действие пользователя. Хранить последнюю собственную транзакцию: приложение/PID, идентификатор контекста, исходный и итоговый фрагмент, раскладки, epoch, время. Отмена разрешена только пока цель и контекст всё ещё валидны. При неопределённости отменить операцию до удаления текста.

[NSPasteboard](https://developer.apple.com/documentation/appkit/nspasteboard) поддерживает несколько items и форматов; general pasteboard участвует в Universal Clipboard. [changeCount](https://developer.apple.com/documentation/appkit/nspasteboard/changecount?changes=l_6) позволяет обнаружить смену владельца. Проектное следствие: сохранять доступные representations всех items, восстанавливать только если clipboard всё ещё принадлежит нашей операции; новое копирование пользователя не затирать. Lazy/promised и несериализуемые representations означают, что идеальный backup не всегда возможен — явно определять отказ/ограничение. Для современных macOS дополнительно проверить pasteboard access policy и отказ пользователя; не обещать универсальный скрытый clipboard fallback.

## 7. Sandbox, распространение и автозапуск

[Apple App Sandbox](https://developer.apple.com/documentation/security/protecting-user-data-with-app-sandbox) относит assistive Accessibility API к несовместимой функциональности. [Ответ Apple DTS](https://developer.apple.com/forums/thread/789663) подтверждает конфликт с требованием sandbox для Mac App Store. Основной исследователь посредством REA `inspect_signature` установил для эталона `app-sandbox=true` и hardened runtime; следовательно, нельзя объявлять сам класс продукта несовместимым с MAS. Ограничение относится к выбранной AX-архитектуре, а разрешение Accessibility и использование AXUIElement — разные вещи. Event-tap/TIS вариант необходимо прототипировать в sandbox с фактическими правами и подписанной сборкой. Developer ID/notarization остаётся вариантом распространения, особенно если выбран AX; MAS требует отдельной проверки работоспособности и ревью. Наличие Caramba в магазине не является гарантией принятия нового приложения.

Для macOS 12: bundled login helper в `Contents/Library/LoginItems`, включаемый через [SMLoginItemSetEnabled](https://developer.apple.com/documentation/servicemanagement/smloginitemsetenabled(_:_:)?language=swift). Для macOS 13+: [SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice), регистрация main app или helper, показ реального `status`, обработка approval/rejection. Не сохранять «включено» только потому, что нажата галочка. После обновления с 12 на 13 не запускать одновременно legacy helper и main app.

## 8. Архитектурные варианты

| Вариант | Оценка |
|---|---|
| Swift/AppKit | Предпочтителен и соответствует выбору пользователя: NSStatusItem, настройки, контролируемый lifecycle, системные адаптеры без дополнительного runtime |
| SwiftUI + AppKit bridge | Возможен для настроек; event tap, TIS, AX и macOS12 status-item всё равно требуют native слоя. Не даёт преимуществ ядру обработки |
| Flutter/Electron shell + Swift native service | Дополнительный межпроцессный/FFI контракт, runtime, память и упаковка; для данного компактного background utility не оправдан |

Проектная граница: чистое детерминированное linguistic core не зависит от AppKit; системные адаптеры поставляют нормализованные события и исполняют проверенные транзакции. UI работает на main thread. Языковая модель загружается атомарно как неизменяемый snapshot; незавершённая загрузка не видна callback. Универсальная сборка содержит arm64+x86_64; тесты обеих архитектур нужны отдельно от факта сборки universal binary.

## 9. Проверяемые платформенные испытания

| Испытание | Проверяемый результат |
|---|---|
| Нет/отозваны listen/post/AX права | Нет удаления или поглощения обычного ввода; понятное состояние UI |
| Tap timeout | Ограниченное восстановление; нет дублей событий и зацикливания |
| Смена приложения/поля во время решения | Транзакция не применяется к новому полю |
| Secure Input включён посреди слова | Буфер очищается; чужой защищённый ввод не сохраняется |
| Внешняя смена раскладки | Кэш/контекст обновляется; нет обратного самопереключения |
| Russian/Russian-PC, Caps Lock, Shift | Верные буквы и пунктуация, без потери пользовательских modifiers |
| Emoji/combining marks/IME/dead keys | Нет частичного удаления Unicode/composition; неподдержанное пропускается |
| Быстрый набор и autocorrect редактора | Ни потери, ни перестановки, ни повторной замены событий |
| Отмена после исправления, затем после ручного редактирования | Первая безопасно возвращает своё изменение; вторая не повреждает новый текст |
| Clipboard plain+RTF+HTML+image+multi-item | Восстановлены все поддержанные representations либо операция корректно отклонена |
| Пользователь копирует во время clipboard операции | Новое содержимое остаётся; восстановление старого не выполняется |
| TextEdit, Safari/Chromium inputs и contenteditable, Electron, terminal, IDE | Отдельный результат для каждого control/editor; никаких blanket promises |
| Автозапуск 12 и 13+, logout/login, обновление, пользовательский запрет | Одна копия процесса, состояние соответствует системе |
| arm64 и x86_64, sleep/wake, смена сессии | Работа восстанавливается с чистым контекстом, без старых замен |

Это предлагаемые acceptance tests. В рамках данного документа они не выполнялись.
