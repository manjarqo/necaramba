## Правила интерпретации

`artifact` — байты, метаданные и ресурсы конкретной сборки; `decompiled` — результат декомпилятора, возможны ошибки типов и восстановления потока; `runtime-ui` — наблюдённые элементы интерфейса; `runtime-behavior` — только реально исполненный сценарий; `vendor-claim` — документация разработчика; `design` — предлагаемое поведение аналога; `unknown` — недостаточно данных.

Оригинальные исходники, комментарии, имена всех локальных переменных и серверная реализация не восстанавливаются автоматически. Счётчик декомпилированных функций означает покрытие распознанных процедур выбранного image, а не полное понимание всех исполнений. Статические ссылки на API не доказывают вызов в конкретном сценарии.

## Инструменты и исходные артефакты

- REA 6.4.0 через CLI и отдельную stdio MCP-сессию; штатный список инструментов текущего Codex не содержал REA.
- Ghidra 12.1.4, официальный release ZIP, SHA-256 `ddac49f903da9d5bac833e5cc79395098b9c33cfd3279be5f31bd00387d2d4db`.
- Архив распакован в `~/.cache/necaramba-tools/ghidra_12.1.4_PUBLIC`; native decompiler для arm64 собран из поставляемого исходного кода с `make ghidra_opt`, `ARCH_TYPE=-arch arm64`, `-mmacosx-version-min=12.0`. Лог `evidence/ghidra-native-build.log`.
- Существующий OpenJDK 21; системные otool/nm/lipo/swift-demangle/assetutil и безопасное чтение plist.
- CUA: просмотр целевого приложения и его настроек. Изменения TCC не выполнялись.
- Основной executable universal SHA-256 `eb77b69bfb9bb6df3231a7ebafe0b9194b53df1c0ff4a673feaa4a5c5b50e051`.
- Анализируемая arm64-копия выделена `lipo -thin arm64`; оригинальный установленный app не изменялся. x86_64-копия сохранена отдельно.

## Наблюдаемые ограничения и исправления инструментария

1. `open_binary.snapshot_path` оказался входным путём существующего snapshot: попытка с новым путём вернула missing, анализ не начался; повтор выполнен без параметра.
2. Ghidra provider не принимает universal Mach-O без явно выбранной тонкой копии; создана arm64-копия.
3. REA-сервер, запущенный до установки движка, сохранил старую диагностику; перезапущен после успешного doctor. Настройки других агентов не менялись.
4. Физические сценарии ввода пока не подтверждены: CUA tile не сообщает checked state; чтение точного preference plist заблокировано ОС. Активный TIS источник доступен. Подробности в `physical-input-test-protocol.md`.
